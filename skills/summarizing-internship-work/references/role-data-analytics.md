# Data Analytics Role Guide

## Typical Chain Evidence

Trace data analytics chain evidence from source fields and ingestion through transformations, SQL models, metric definitions, quality checks, scheduling, dashboards, exports, and consumers. Cite query logic, grouping/filtering, tests, and lineage.

## Impact Dimensions

Assess metric correctness, reproducibility, data quality, lineage clarity, freshness, interpretability, stakeholder usefulness, performance, and maintenance. Distinguish a query's behavior from a business decision or outcome.

## Evidence Topics

Use dataset and reporting scope, metric definitions, quality checks, consumers, and validated decision or business metrics as evidence topics. Route material gaps through the main consolidated confirmation process; this guide does not add confirmation rounds or request Git identity for a named-feature route.

## Pitfalls

Do not infer revenue, adoption, decision quality, data freshness, or accuracy from SQL presence alone. Avoid exposing sensitive rows, customer fields, credentials, or private dashboard links.

## Career Framing

Frame career evidence around converting a question into a traceable model or analysis, defining trustworthy metrics, and enabling reviewable decisions. Use outcome metrics only when independently confirmed.
