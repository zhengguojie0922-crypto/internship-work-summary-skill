# Backend Role Guide

## Typical Chain Evidence

Trace backend chain evidence across route registration, request validation, authorization, service calls, domain logic, persistence, migrations, events, configuration, tests, and downstream clients. Connect definitions and calls with commits and exact paths.

## Impact Dimensions

Assess correctness, data integrity, API clarity, reliability, security, performance, operability, maintainability, and cross-service compatibility. Distinguish code capability from deployed system outcome.

## Evidence Topics

Use service scope, prior behavior, contract changes, failure handling, test coverage, and runtime or business evidence as evidence topics. Route material gaps through the main consolidated confirmation process; this guide does not add confirmation rounds or request Git identity for a named-feature route.

## Pitfalls

Do not infer traffic, uptime, latency improvement, incident prevention, or sole service ownership from code. Keep schema, client, infrastructure, test, and reviewer contributions separately attributed.

## Career Framing

Frame career evidence around dependable contract design, domain reasoning, consistency, failure handling, and collaboration across boundaries. Include metrics only when a cited source confirms them.
