# Frontend Role Guide

## Typical Chain Evidence

Trace frontend chain evidence from route or UI text through component registration, state and data fetching, rendering, styling, accessibility, analytics events, browser tests, and the API boundary. Cite component definitions, imports, call sites, state transitions, and related commits.

## Impact Dimensions

Assess user workflow, interaction clarity, accessibility, compatibility, responsiveness, maintainability, client performance, error handling, and delivery collaboration. Treat observed implementation as capability evidence; require separate evidence for user or business outcomes.

## Evidence Topics

Use browser or user problem context, consumed API contracts, behavior tests, and product metrics or feedback outside Git as evidence topics. Route material gaps through the main consolidated confirmation process; this guide does not add confirmation rounds or request Git identity for a named-feature route.

## Pitfalls

Do not equate a component file with end-to-end ownership. Do not infer adoption, conversion, latency, accessibility compliance, or production scale. Separate design, API, rename, review, and test contributions.

## Career Framing

Frame career evidence around translating a user flow into maintainable UI behavior, coordinating contracts, handling edge states, and verifying quality. Use metrics only when confirmed and cited.
