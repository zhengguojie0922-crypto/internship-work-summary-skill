# DevOps Role Guide

## Typical Chain Evidence

Trace DevOps chain evidence through workflow triggers, build/test jobs, artifact creation, infrastructure definitions, configuration, secrets references, deployment stages, health checks, rollback, monitoring, and incident changes. Stop at external platform boundaries unless evidence is available.

## Impact Dimensions

Assess repeatability, release safety, recovery, observability, security, cost awareness, environment consistency, lead time, and operational maintainability. Separate configured capability from actual execution.

## Evidence Topics

Use environment scope, pipeline execution evidence, operational motivation, rollback and secret handling, and deployment or incident metrics as evidence topics. Route material gaps through the main consolidated confirmation process; this guide does not add confirmation rounds or request Git identity for a named-feature route.

## Pitfalls

Do not infer successful deployment, reduced time, uptime, cost savings, or incident prevention from configuration alone. Redact secrets and distinguish configuration author, operator, approver, and service owner.

## Career Framing

Frame career evidence around automating a reproducible delivery path, adding safety controls, and improving operational visibility. Use metrics only from cited run or operational evidence.
