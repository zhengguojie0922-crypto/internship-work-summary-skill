# Algorithm Role Guide

## Typical Chain Evidence

Trace algorithm chain evidence through problem formulation, inputs/features, preprocessing, model or optimization logic, training/inference, evaluation, baselines, experiments, integration, monitoring, and tests. Require actual algorithm artifacts, not adjacent API or UI files.

## Impact Dimensions

Assess correctness, evaluation rigor, quality/latency trade-offs, robustness, reproducibility, explainability, resource efficiency, integration, and monitoring. Separate implementation quality from measured model or product impact.

## Evidence Topics

Use the algorithm artifact location, attribution, baseline and evaluation, leakage or bias controls, integration, and experiment metrics as evidence topics. Route material gaps through the main consolidated confirmation process; this guide does not add confirmation rounds or request Git identity for a named-feature route.

## Pitfalls

Do not label ordinary CRUD, API wiring, or UI consumption as algorithm work. Do not invent novelty, accuracy, lift, dataset scale, or sole model ownership. State when repository scope contains no supporting implementation.

## Career Framing

Frame career evidence around formalizing the problem, implementing and evaluating a method, reasoning about trade-offs, and integrating it responsibly. Use metrics only from cited evaluation evidence.
