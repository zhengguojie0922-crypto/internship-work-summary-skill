# Client Role Guide

## Typical Chain Evidence

Trace client chain evidence through screen or view registration, navigation, local state, platform lifecycle, API/storage integration, offline behavior, permissions, packaging, telemetry, and device tests. Connect shared and platform-specific layers.

## Impact Dimensions

Assess user workflow, lifecycle correctness, resilience, compatibility, offline behavior, resource use, accessibility, release safety, and maintainability across platforms.

## Evidence Topics

Use client platform scope, platform constraints, lifecycle and failure-state tests, consumed server contracts, and release evidence as evidence topics. Route material gaps through the main consolidated confirmation process; this guide does not add confirmation rounds or request Git identity for a named-feature route.

## Pitfalls

Do not treat shared API code as proof of client authorship. Do not infer store adoption, crash reduction, performance, device reach, or production behavior. Separate API, platform, release, and test contributions.

## Career Framing

Frame career evidence around turning a platform requirement into robust client behavior, managing lifecycle and integration boundaries, and validating release quality. Use metrics only with direct evidence.
